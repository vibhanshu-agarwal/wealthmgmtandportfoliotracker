## Emergent conflicts and rulings

- Ruling: D5's fixed `${server.port}` / `localhost` wording is stale against the later authoritative Task 8.3/8.5/8.7a and kickoff contract. Freeze the implementation on `Environment.getProperty("local.server.port")` at subscription/call time, through an injectable loopback-target seam; amend D5 during Task 1. Cost if wrong: a RANDOM_PORT integration failure exposes the mismatch immediately.
- Ruling: eligibility is unknown until the read completes, so the single eligibility GET runs after every successful demo authentication/JWT mint, not only on already-known idle-eligible logins. Ordinary users and failed auth issue no call. Amend stale D5 frequency prose. Cost if wrong: reduced reset attempts or calls on the wrong identity.
- Ruling: ordinary idle-ineligible completion is a clean no-op, not a failure skip, and emits no `demo_reset_self_call_skipped` event. The stable reason vocabulary has no ineligible reason and Task 8.7 defines events for non-clean outcomes. Cost if wrong: operational noise and an ungoverned reason value.
- Ruling: an already-dispatched reset may commit after either the reset-leg timeout or the overall timeout cancels the gateway subscription. Task 8.9 Class 2f/2g's assertion that dual events are coherent only for `overall_timeout` is unsafe, especially when the per-leg reset timeout fires before the overall deadline. Amend the classifier and verifier tests to admit `reset_timeout` + success as a timeout-boundary outcome; do not relabel the gateway event. Cost if wrong: false rollback/abort classification of a real persistence race.
- Ruling: the three-phase timeout model is insufficient because the overall deadline starts before eligibility-target construction and remains active while reset-response handling completes. Freeze five observable phases: `eligibility_pre_dispatch`, `eligibility_in_flight`, `between_legs`, `reset_in_flight`, and `reset_post_response`. Phase and dispatch facts must agree; `attemptedTarget` remains null when no self-call is in flight. Cost if wrong: diagnostics can claim a call was attempted when cancellation occurred before dispatch, or hide a post-response race.
- Ruling: the loopback-target seam must be subscription-time, nonblocking, and cancellable (for example a deferred `Mono<URI>` or equivalent). It must resolve `local.server.port` at call time and support deterministic pre-dispatch cancellation without blocking sleeps. Cost if wrong: the overall timeout cannot safely cover target construction and RANDOM_PORT tests can capture stale endpoints.
- Ruling: timeout elapsed time uses a monotonic seam (`LongSupplier`/`System.nanoTime` equivalent); idle age uses an injected UTC `Clock`. Wall-clock time must not drive elapsed timeout diagnostics. Cost if wrong: clock adjustments can corrupt timeout ordering and recorded latency.
